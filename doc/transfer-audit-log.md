- 식당OS의 "기존 3단계 타임라인"(`BuyOrderTimeline.tsx`)도 `commerce_orders.status`를 읽는다.
- **판단**: 배송 추적 대상은 `commerce_orders`.

### C-04. 테스트 수단
- 로컬에 `psql`/`docker` 없음. 레포에 테스트 러너 없음.

### 0-02. "선물답게" → "식식이" 치환의 예외 3곳
치환 규칙은 "브랜드명 등장하는 모든 곳"이다. 다만 아래 3곳은 그대로 치환하면 **사실이 아닌 문장**이 된다.

| 위치 | 원문 | 처리 | 이유 |
|---|---|---|---|
| 문서 머리 | "선물답게(kojomo-special)에 구현된…" | 출처 표기 1줄로만 남김 | 출처를 지우면 이 문서가 무엇의 재가공인지 추적이 끊긴다 |
| 원칙 5 | "선물답게에서 실제로 9곳이 발견됐고" | "원문(선물답게)에서" | 식식이에서 9곳이 발견된 게 아니다. 치환하면 거짓 사실이 된다 |
| 6절 현재 상태 표 | "배송 추적 구현 완료(DB 0014·0015 적용)" | 식식이OS 이식 상태 표로 교체 | 식식이에는 아직 없다. 치환하면 "구현 완료"라는 거짓 상태가 된다 |

**설계 원칙 문장은 한 곳도 바꾸지 않았다.** 바뀐 것은 용어와, 위 3곳의 "사실 주장"뿐이다.

### 0-03. "고객사" 치환 판단 — 공급자 vs 관리자
원문의 고객사는 "선물을 보내는 기업(구매 담당자)"이다. 식식이 storefront에서 주문·고객·결제의 1차 owner는 **플랫폼(관리자)** 이고 공급자는 fulfillment allocation 축에서만 연결된다(`docs/CONTEXT.md` commerce_orders 행).

| 원문 문장 | 치환 | 판단 |
|---|---|---|
| 3-3 "한 채널로 여러 **고객사**의 메시지를 보낸다" | 공급자 | 명의가 여러 개로 갈릴 수 있는 주체는 상품을 실제로 보내는 공급자다 |
| 3-3 "**고객사**마다 채널을 만들지 않는다" | 공급자 | 위와 같은 축 |
| 3-3 "보내는 분: 주식회사 ABC 대표이사 홍길동" | "보내는 분: OO식자재 (공급자)" | 사용자 지시서 3단계 4번 "실제 발신자(공급자) 표시" |
| 3-3 "**고객사**가 설정하는 것: 사용 여부 / 발송 모드 / 보내는 분 표기 / 감사 메시지" | **관리자** — ⚠️ 확인 필요 | 공급자가 직접 설정하게 할 수도 있다. 하지만 공급자에게 발송 스위치를 주면 공급자 명의로 식당에 메시지가 나가는 권한이 생긴다. 지시서 규칙 "애매하면 보수적인 쪽(관리자가 설정)"을 따랐다 |
| 3-4 "**고객사** 명의로 나가는 메시지에 우리 판매 문구를 넣지 않는다" | 공급자 | 명의 주체 = 공급자 |
| 3-5 "**고객사** 화면에는 전체 100명 / 전달 98 / 실패 2" | **관리자** — ⚠️ 확인 필요 | 설정 주체를 관리자로 정했으므로 결과 화면도 관리자. 공급자에게 자기 명의 발송 결과를 보여줄지는 사장님 판단 사항 |

### 0-04. 원문을 바꾸지 않고 둔 비교 문장
- 1-4절 끝 "기업 담당자가 견적을 받기 전에 확인하는 것과 구조적으로 같다" — 이 문장은 **원문 도메인과 식식이 도메인을 비교하는 문장**이다. "기업 담당자"를 공급자/관리자로 바꾸면 비교 자체가 무너진다. "원문에서 기업 구매 담당자가…"로 출처만 밝히고 유지했다.

### 0-05. 원문 안의 표현 불일치 — 고치지 않고 메모만
- 2-2절 규칙: "모르는 값은 **조회 오류**로 둔다" / 원칙 2: "모르는 값은 추측하지 않고 **확인 필요**로 둔다". 원문 자체가 다르다.
- **판단**: 원칙 문장은 바꾸지 말라는 지시에 따라 둘 다 유지. 구현은 **2-2절(조회 오류)** — 사용자 지시서 1단계 3번이 "조회오류"로 명시했다.

### 0-06. "7단계"인데 이름은 8개
- 원문 상태 목록: 송장 등록 전 / 배송 준비 / 집화 / 배송 중 / 배달 중 / 배송 완료 / 확인 필요 / 조회 오류 = **8개**. 원문과 지시서 모두 "7단계"라 부른다.
- **판단**: 이름 8개를 하나도 빼지 않는다(무엇을 뺄지 고르는 것 자체가 추측이다). "진행 6단계 + 예외 2개"로 구현하고, 문서 명칭 "7단계"는 원문 그대로 둔다.
