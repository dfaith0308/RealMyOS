## 0. 먼저 읽을 것 — 조사 중 발견한 3가지 함정

### ⚠️ 함정 1. 로컬 `main` 브랜치가 심하게 낡아 있다

```
RealMyOS       로컬 main = bf5e7bc (08-31)   ←→   origin/main = c01b886 (09-09)
restaurant-os  로컬 main = 9856784 (08-03)   ←→   origin/main = 82d1910 (09-09)
```

로컬 `main`으로 비교하면 **restaurant-os는 37일치가 미배포인 것처럼 보인다.** 실제로는 아니다.
**→ 이 보고서의 모든 비교는 `origin/main` ↔ `origin/dev` 기준이다.**

### ⚠️ 함정 2. `git log main..dev` 로는 답이 안 나온다 — 체리픽 워크플로다

두 레포 모두 **dev의 일부 커밋만 골라 main 위에 다시 얹는(cherry-pick) 방식**이다. 같은 메시지·같은 시각이지만 **SHA가 다르다.**

| | RealMyOS | restaurant-os |
|---|---|---|
| `origin/main..origin/dev` (dev에만 있는 커밋) | 22 | 13 |
| `origin/dev..origin/main` (main에만 있는 커밋 = 체리픽 사본) | 8 | 4 |
| 분기점(merge-base) | `bf5e7bc` 08-31 | `9856784` 08-03 |

즉 두 브랜치는 **08-31 / 08-03 이후로 갈라진 채 각자 진행**됐고, 커밋 개수만 세면 실제 코드 차이를 크게 부풀려 읽게 된다.

### ⚠️ 함정 3. `git cherry` 도 틀린다 — **트리 차이가 유일한 정답**

체리픽하면서 내용이 조금 바뀌면 patch-id가 달라져 `git cherry`가 "main에 없음(+)"으로 오판한다.

- 실제 오판 사례: RealMyOS `793765c`(리스팅 이관 P3)를 `+`로 표시했지만, 해당 파일(`commerce-listing-transfer.ts`)은 트리 차이에 **없다** → 이미 main에 있다.
- restaurant-os `69e7dc2`도 동일 (`buy-discount.ts`가 트리 차이에 없음).

**→ 이 보고서는 `git diff --name-only origin/main origin/dev` 결과를 정답으로 삼고, 커밋 목록은 그 위에 얹어 해석했다.**

- `vercel.json`에 `"path": "/api/cron/billing-renewal", "schedule": "0 0 * * *"` (매일 자정) 추가 — **이 파일이 dev에만 있다**

> **대신 그 자리에 들어가야 할 진짜 보안 항목은 `message_logs`·`quote_logs`다** — RLS가 꺼진 채 `anon`에 `SELECT/INSERT/UPDATE/DELETE/TRUNCATE` 전권이 부여돼 있고, 익명 키로 메시지 본문 3행 전부가 읽힌다. `overnight-audit-log.md` §6-2 참조.
