# UI/UX Redesign Audit (Phase 1)

목표는 “ERP 리스킨”이 아니라 **외식 공급망 운영 OS**로의 재정의입니다. 아래 내용은 화면별로 “왜 촌스럽고 ERP 같아 보이는지”를 냉정하게 해부하고, **Side Panel 금지 / 행 클릭=페이지 이동 유지** 전제에서 **구조적으로 바꿔야 하는 것**을 정리합니다.

## 공통 문제 (전 화면)
- **토큰 부재**: 인라인 스타일 + 하드코딩 hex가 분산되어 화면마다 톤이 갈라짐 → “제품”이 아니라 “기능 조각” 인상.
- **정보 계층 붕괴**: KPI/상태/다음 행동이 동일한 시각적 레벨에서 경쟁(카드/버튼/배지 모두 같은 무게).
- **상태 언어 미정**: confirmed/pending/cancelled/overdue가 화면마다 다른 형태/색/텍스트로 표현됨 → 사용자는 매번 다시 학습.
- **테이블이 CRUD**: 운영툴이라기보다 “관리자 페이지” 느낌(라인 높이/정렬/숫자 가독성/행 포커스/액션 위치가 불명확).
- **숫자 우선 실패**: 통화/수량/마진 같은 핵심 숫자가 작은 폰트/약한 대비/불안정한 정렬로 표시됨.

## Sidebar (Supplier OS · realmyos)
### 왜 ERP처럼 보이는가
- 메뉴가 **업무 흐름이 아니라 모듈 나열**로 보임(“오늘 해야 할 일”이 아닌 “기능 목록”).
- active/hover가 “탭” 느낌만 내고, **현재 컨텍스트(작업 영역/필터/기간/테넌트)** 가 유지되지 않음.

### 운영 콘솔로 바꾸려면 (Phase 2 구조 변경 포인트)
- 네비를 **업무 영역 중심**으로 재정렬: (예) 수금·미수·원장 / 주문·납품 / 거래처 / 분석 / 설정.
- 상단에 “현재 작업 컨텍스트”(기간/테넌트/권한)를 얇게 노출해 **콘솔** 느낌 강화.
- 메뉴는 아이콘보다 **텍스트 명확성 + 밀도**가 우선(Linear 스타일).

## Dashboard (Supplier OS · realmyos)
### 왜 촌스럽고 ERP 같은가
- KPI 카드가 “예쁘게 보이기” 중심으로 분절되어 있고, **우선순위(연체/주의/리스크)** 가 전면에 오지 않음.
- “다음 행동”이 없다: 연체가 보이더라도 클릭 후 어디로 가야 해결되는지(수금 등록/연체 거래처/미결 주문) 연결이 약함.

### 운영 센터로 바꾸려면
- 상단 KPI는 3~5개로 압축하고 **연체/현금흐름/마진** 같은 “대표가 보는 숫자”를 가장 큰 계층으로.
- 그 아래는 카드가 아니라 **업무 큐(Queue)**: “오늘 처리할 항목” (연체 거래처, 미확정 주문, 승인 대기, 미발행 문서 등)
- KPI는 `KPIBlock`로 숫자 계층 고정 + 상태 배지/델타 표준화.

## Orders (Supplier OS · realmyos)
### 왜 CRUD 테이블처럼 보이는가
- 주문 목록이 상태/우선순위보다 컬럼 나열에 치중.
- 행 hover/focus/선택/액션 위치가 일정하지 않아 “업무 리스트”가 아니라 “DB 레코드 표”처럼 보임.

### 운영툴답게 바꾸려면
- 행에서 가장 먼저 보여야 하는 건 “상태 + 금액 + 기한(납기/약속)” + 거래처.
- 필터는 “상태 기반”으로 간결화(confirmed/pending/cancelled + overdue).
- Row는 `DataTableRow` 패턴으로 고정(숫자 우측정렬, tabular nums, keyboard focus).

## Customers (Supplier OS · realmyos)
### 왜 ERP 같은가
- 거래처 리스트가 “명단”에 가까움. 운영 관점(위험/연체/거래 빈도/마진/수금 패턴)의 시그널이 약함.

### 구조적으로 바꿔야 할 것
- 거래처 row에서 “리스크/연체/미수”를 한 눈에: `StatusBadge` + 핵심 숫자 1~2개.
- 상세 페이지는 “요약(신호) → 근거(원장)” 흐름으로.

## Ledger (Supplier OS · realmyos)
### 왜 복잡하고 ERP 같은가
- 원장이 “모든 것을 다 보여줌”으로 흐르고, 사용자가 실제로 필요한 **요약→근거 탐색** 경로가 약함.
- 결제/수금/미수 상태가 텍스트·색으로만 흩어짐.

### 운영형 구조 제안
- 상단에 “미수/연체/최근 수금” 같은 **결론 블록**을 고정(KPIBlock).
- 아래 라인은 `DataTableRow` 기반으로 밀도/정렬을 통일하고, 상태는 `StatusBadge`로 통일.
- (중요) Side Panel 금지 유지: 행 클릭은 상세 페이지로, 대신 리스트 자체의 정보 밀도를 높여 “클릭 필요성”을 줄임.

## Today (Restaurant OS · resturant_os)
### 왜 B2C/카드앱 느낌이 나는가
- 카드/이모지/큰 여백이 “소비자 앱” 톤을 만들고, 현장 운영에서 필요한 **결정/승인/확인** 흐름이 약함.
- BottomNav 라벨이 “업무 행위”보다 “탭” 느낌에 가깝다.

### 현장 운영 도구로 바꾸려면
- Today는 “피드”가 아니라 **업무 큐**: 승인/확인/발주/알림을 우선순위로 정렬.
- 숫자(오늘 발주/확정/미확인)와 상태(대기/확정/주의)를 작은 컴포넌트로 빠르게 스캔 가능하게.
- 터치 타겟은 키우되, 시각적 요소는 절제(카드 남발 금지).

## Phase 2 시작 조건
- Phase 1의 `design-system.ts` + `--ds-*` + `StatusBadge/Surface/DataTableRow/KPIBlock`를 기반으로, 실제 화면에서 하드코딩 스타일을 제거하며 구조를 바꾼다.
